# 직무발명신고서 자동 작성 시스템 — 아키텍처 확정 문서

> 발명자가 자유 형식 특허 아이디어 문서(PPTX 등)를 업로드하면, Wrks.ai로
> AMO그룹 표준 직무발명신고서(PPTX)를 자동 작성·검토·다운로드하는 사내 웹앱.

---

## 1. 확정된 사실 (검증 완료)

### 1.1 Wrks.ai API 키 검증 결과
- 발급 키 `patent-idea-sheet-key` (`wrks_49aa...`) 는 **정상 동작**함 (실제 호출 확인).
- 이 키는 **기업 계정 관리 API**(`https://gateway-api.wrks.ai`) 용이며, 헤더 `API-KEY`로 인증.
- 검증된 엔드포인트:
  | 엔드포인트 | 상태 | 반환 |
  |---|---|---|
  | `GET /admin/users` | 200 | 전 직원 341명 (이름·이메일·사번·부서·워크스페이스·role) |
  | `GET /admin/departments` | 200 | 부서 트리 (기획조정실/기술법무팀 등) |
  | `GET /admin/workspaces` | 200 | 워크스페이스별 허용 모델: `gpt-4.1`, `o3-mini`, `o1`, `gpt-4o-2024-11-20`, `gpt-4.1-nano` |

### 1.1.1 구현 중 확인된 API 세부사항 (P2 통합 테스트)
- `/admin/users` 응답 구조: `{ result, data: { users: [...], totalUserCount } }` (이중 중첩).
- **페이지네이션**: 기본 10건. `?limit=1000`으로 전원(341) 일괄 취득 가능. `?page=N` 페이징 지원.
- **직원 필드 실제 키**: `userName`, `email`, `departmentFullName`(예: "기획조정실/기술법무팀"), `workspaceName`, `role`, `departmentCode`.
- ⚠️ **`employeeId`(사번)와 `직위`(position)는 이 API에 없음/null** → 표준양식 발명자 표의 사번·직위 칸은 **발명자 수동 입력**으로 처리하고 `[발명자 확인 필요]` 플래그.
- 법인 매핑은 이메일 도메인 기준 (`amotech.co.kr`→(주)아모텍 등).

### 1.2 확인된 제약 (중요)
- **이 게이트웨이에는 AI 생성(chat/completions) 엔드포인트가 없음** — 20여 경로 전부 404.
  - 단, 공식 문서상 "사내 시스템이 문서를 자동 요약/번역할 때 이 키를 쓴다"고 명시 →
    **AI 생성용 엔드포인트는 존재하나 URL이 비공개**. `support@wrks.ai` 문의 필요.
- **외부 웹앱용 OAuth/OIDC 로그인 기능 없음.** Wrks 공식 SSO는
  `https://wrks.ai/ko/signin/company/{회사코드}?code={암호화코드}` 형태로 **wrks.ai 포털에 자동로그인**
  시키는 방식이고, 그 **암호화 키는 API 키와 별개**로 `support@wrks.ai`에서 받아야 함.
  - 평문 포맷: `이메일|timestamp(YYYYMMDDHHmmss)|이름` → 회사 제공 키로 암호화.

### 1.3 PPTX 처리 기술 검증 (PoC 통과)
- `python-pptx`로 표준양식 표 셀에 값 주입 → 저장 → 재오픈 → 값·무결성 확인 **성공**.
- 발명자 원본 슬라이드를 표준양식 뒤에 복제·병합 **성공** (텍스트 이관 확인).
  - ⚠️ 이미지(개념도) 이관은 relationship(rId)까지 재작성 필요 — 구현 시 별도 처리.

## 2. 표준양식 PPTX 셀 매핑 (자동 채움 대상)

표준양식은 5면. **채움 대상은 2·3면** (4면 안내는 삭제, 5면은 회사 기재란=공란 유지).

### 2면 — 신고 기본사항 및 발명자 (`Table 0`, `Table 1`, `Table 2`)

**Table 0 (4×4) — 기본사항**
| 셀 | 항목 | 채움 소스 |
|---|---|---|
| (0,1) | 발명의 명칭(국문) | AI 추출 |
| (1,1) | 신고 법인 | 로그인 사용자 소속(법인) |
| (1,3) | 발명 완성일 | **발명자 입력** (AI가 문서 날짜로 추정 제안) |
| (2,1) | 신고 구분 | 기본 "직무발명 완성사실 신고" 체크 |
| (2,3) | 발명 완성도 | AI 추정 (착상/실험/시제품/양산) |
| (3,1) | 관련 제품·적용처 | AI 추출 |
| (3,3) | 출원 희망 | 발명자 선택 |

**Table 1 (6×8) — 발명자**  (헤더: 구분/성명/사번/소속/직위/이메일/기여율/서명)
| 행 | 채움 소스 |
|---|---|
| (1,1~6) 대표발명자 | **로그인 사용자 정보 자동 채움** (`/admin/users`에서 이름·사번·부서·이메일) |
| (2~4) 공동발명자 | 발명자가 추가 입력 (이름 입력 시 `/admin/users`에서 자동완성) |
| (5,6) 기여율 합계 | 항상 100 검증 |

**Table 2 (3×2) — 법적 필수 항목** (전부 **발명자 입력**, AI 자동 판단 금지)
| 셀 | 항목 |
|---|---|
| (0,1) | 국가R&D 과제 해당 여부 |
| (1,1) | 외부 공동개발 여부 |
| (2,1) | 공개 이력 (미공개/공개/공개예정) |

### 3면 — 발명의 요지 (`Table 0` 5×2) — **AI 자동 채움 핵심**
| 셀 | 항목 | AI 프롬프트 대상 |
|---|---|---|
| (0,1) | 1. 기술분야·적용 대상 | 원본 요약/명칭에서 추출 |
| (1,1) | 2. 종래기술과 문제점 (선행자료·출처) | 원본 "기술적 과제" 등에서 |
| (2,1) | 3. 해결하려는 과제 | 원본에서 |
| (3,1) | 4. 핵심 구성과 작동원리 | 원본 "발명의 구성"에서 |
| (4,1) | 5. 종래기술 대비 효과 (정량) | 원본 "기대효과"에서, **미확인 수치는 생성 금지** |

- 3면 하단 `Table 1` (신고일/대표발명자/부서장) 서명란은 공란(오프라인 서명) 또는 발명자 입력.
- **4면 이후**: 발명자 원본 슬라이드(개념도 이미지 포함) 그대로 이관.

### AI 생성 규칙 (표준양식 1면 "작성 원칙" 반영)
- 일반 기술용어 사용, 사내 약어는 최초 1회 전체 명칭 병기.
- 같은 구성요소는 문서 전체에서 동일 용어.
- **확인되지 않은 수치·효과는 생성하지 않음** (환각 방지 — 법적 리스크).
- 부족한 항목은 "[발명자 확인 필요]" 플래그로 표시하여 사람이 채우도록 유도.

## 3. 시스템 아키텍처

```
[발명자 브라우저]  ── HTTPS ──▶ [Apache (기존 IPMS, 210.122.45.104)]
                                      │  ProxyPass /invention → localhost:8080
                                      ▼
                             [Node.js 백엔드 (Express/TS)]
                              ├─ AuthAdapter   ── (dev) 이메일 대조 → /admin/users
                              │                   (prod) Wrks 암호화코드 SSO
                              ├─ AIAdapter     ── (dev) Mock / OpenAI 호환
                              │                   (prod) Wrks AI 생성 API
                              ├─ PPTX Engine   ── 표준양식 채움 + 원본 슬라이드 병합
                              └─ (선택) 세션/이력 저장 (SQLite)
```

### 3.1 인증 어댑터 (교체 가능)
- **인터페이스**: `authenticate(req) → { email, name, employeeId, dept, company }`
- **개발 구현 (`EmailDirectoryAuth`)**: 발명자가 회사 이메일 입력 → 백엔드가
  `GET /admin/users?email=...`로 **실재 직원인지 대조** → 통과 시 세션 발급.
  발급 키를 실제로 활용하므로 "회사 사람만 통과"가 지금 바로 동작.
- **운영 구현 (`WrksEncryptedSsoAuth`)**: 그룹웨어/IPMS에서 `이메일|ts|이름` 암호화 코드로
  진입 → 복호화·검증. (Wrks 암호화 키 확보 후 활성화)
- **키 보안**: 관리자 API 키는 **전 직원 개인정보 조회 가능** → 반드시 백엔드 전용,
  브라우저 노출 금지, `.env`로 주입. Wrks **API 키 허용 IP에 210.122.45.104 공인 IP 등록 권장**.

### 3.2 AI 어댑터 (교체 가능)
- **인터페이스**: `generateSheet(extractedText) → { title, applications, completeness, 요지5항목, flags[] }`
- **개발 구현**: `MockAIProvider`(규칙 기반) 또는 `OpenAICompatProvider`(OpenAI 호환 base URL).
- **운영 구현**: `WrksAIProvider` — base URL/헤더만 교체 (support@wrks.ai 스펙 확보 후).
- 모델: `gpt-4.1` / `gpt-4o` 계열 (워크스페이스 허용 목록과 일치).

### 3.3 PPTX 엔진
1. **입력 파싱**: 업로드 PPTX/PDF/DOCX → 텍스트+이미지 추출 (`python-pptx` 등, 자식 프로세스).
2. **AI 구조화**: AIAdapter로 요지 5항목 + 기본사항 초안 생성.
3. **템플릿 채움**: 표준양식 사본에 §2 매핑대로 셀 주입 (서식 보존, 검증됨).
4. **원본 병합**: 4면 안내 삭제 후 원본 슬라이드(이미지 포함) 이관.
5. **산출**: 채워진 `.pptx` (기본). PDF 변환은 옵션(libreoffice headless).

### 3.4 검토·수정 흐름
- 업로드 → AI 초안 → **웹 편집 화면**(각 필드 textarea, `[발명자 확인 필요]` 강조)
  → 발명자 첨삭·공동발명자 추가·기여율 100 검증 → **확정** → PPTX 생성·다운로드.

### 3.5 배포 (Apache 리버스 프록시)
- 기존 IPMS(Apache) 유지. Node 백엔드는 별도 포트(예: 8080) 상주(systemd/pm2).
- Apache VirtualHost에 `ProxyPass /invention http://127.0.0.1:8080/` 추가 → `http://210.122.45.104/invention`.
- 방화벽 화이트리스트(사내) 그대로 적용 → 특허 아이디어 민감정보 외부 차단 유지.
- 산출물은 **가시적 디렉터리**(`output/`)에도 사본 저장.

## 4. 기술 스택 (제안 확정)

| 영역 | 선택 | 비고 |
|---|---|---|
| 백엔드 | Node.js + Express + TypeScript | 배포 단순, 어댑터 패턴 용이 |
| PPTX | Python `python-pptx` (child process) | 채움/병합 PoC 검증 완료 |
| 문서 파싱 | python-pptx / pdfplumber / mammoth(docx) | 형식별 |
| 프론트 | 서버 렌더 HTML + 최소 JS | "html 페이지 배포" 요구 부합 |
| 저장(선택) | SQLite | 초안·이력 |
| 배포 | systemd + Apache ProxyPass | 기존 인프라 재사용 |
